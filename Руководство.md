# Расписание КНиИТ

Распакуйте архив и откройте **Календарь КНиИТ.html** в браузере. Выберите группу по номеру и форме обучения. Поле «Направление» сужает список групп. Переключатель «Числитель / Знаменатель» показывает одну неделю для выбранной группы в календаре, списке по дням и таблице нагрузки. Тип пары подписан справа от времени и задаёт цвет карточки. Неразмещённые занятия выбранной группы и недели доступны над расписанием.

Для пересчёта откройте терминал рядом с файлом **raspisanie_sgu.py**. Подходит Python 3.10 или новее. Используется стандартная библиотека Python.

## Запуск

```powershell
# Пересчитать все группы и открыть обновлённый календарь
python raspisanie_sgu.py

# Быстрая проверка на небольшом самостоятельном примере
python raspisanie_sgu.py --data examples --summary-only

# Вывод по преподавателю, аудитории или группе
python raspisanie_sgu.py --data examples --variant 1 --view teacher --resource Ильина --week Ч
python raspisanie_sgu.py --data examples --variant 2 --view room --resource А-101 --week З
python raspisanie_sgu.py --data examples --variant all --view group --resource Г-101

# Сравнение четырёх вариантов на реальном каталоге без диалога
python raspisanie_sgu.py --config search_config.json --summary-only

# Просмотр варианта для группы КНиИТ
python raspisanie_sgu.py --variant 1 --view group --resource "КНиИТ / do/111"

# Проверка и воспроизведение эксперимента
python -m unittest discover -s tests -v
python benchmark.py --runs 5 --seed 41 --output report.json
```

После таблицы сравнения в интерактивном терминале можно ввести номер варианта или `all`. Фильтрация применяется после общего расчёта. Статистика поиска относится ко всему вузу, расписание и список пропусков — к выбранным ресурсам. В примере из JSON недели обозначены Ч и З. Для СГУ выводятся также даты из настроек семестра. Ключ `--published` открывает сохранённую сетку сайта. Отдельные программы в папках факультетов предназначены для работы с их локальными данными.

## Структура

| Файл | Назначение |
|---|---|
| `raspisanie_sgu.py` | Запуск, меню СГУ, просмотр исходной сетки |
| `planner/models.py`, `planner/loader.py` | Модели данных и проверка пяти входных JSON-файлов |
| `planner/sgu.py`, `fortnight.py` | Подготовка общей модели из семестровых планов, классов и сохранённого расписания СГУ |
| `planner/constraints.py` | Ограничения, индекс занятости и независимый аудит готового назначения |
| `planner/generation.py` | Построение расписания, снятие и повторное назначение занятия |
| `planner/optimization.py` | Несколько попыток, профили, бюджеты и отбор различных вариантов |
| `planner/evaluation.py`, `planner/weights.py` | Метрики, сходство, базовые и адаптивные веса |
| `planner/console.py`, `planner/reporting.py` | Обработка аргументов и текстовый вывод |
| `examples/` | Пять JSON-файлов и словарь полей «Формат JSON.txt» |
| `tests/test_planner.py`, `benchmark.py` | Сценарии проверки и повторяемый эксперимент |
| `benchmark_results.json` | Замеры по каждому запуску, метрики и агрегаты |

В приложение с GUI можно встроить `load_problem(folder)` и `generate_variants(problem, config)`. Они возвращают модели и назначения без ввода с клавиатуры и печати. Независимая функция `validate(problem, placements, require_complete=True)` перечисляет ошибки, включая отсутствующие занятия.

## Ограничения и нагрузка

Одна заявка объединяет преподавателя, предмет и одну или несколько групп. Один и тот же день, кабинет и время применяются ко всем указанным в заявке неделям. Лабораторная с `duration=2` занимает две последовательные пары на каждой из них. Для занятий с разной периодичностью создайте отдельные заявки. Одна заявка с двумя группами описывает общее занятие. В примере JSON можно задать вместимость, оснащение, разрешённые кабинеты и доступность по каждой паре.

Каждое назначение проверяется по занятости преподавателя, всех групп и физических помещений. Общие части совмещённых аудиторий имеют общие ключи. Проверяются интервалы в минутах между разными сетками звонков, непрерывная длительность и дневной лимит для групп и преподавателей. В базовом наборе лимит равен пяти парам. День с одной парой допустим и получает штраф. В данных СГУ физкультура КНиИТ привязана к стадиону «Локомотив».

В снимке СГУ отсутствуют подтверждённые размеры групп, вместимость многих кабинетов и семестровые часы. Кабинеты выбираются из опубликованных привязок предметов. Без часов используется одна пара на каждую разрешённую неделю. Заданная семестровая нагрузка раскладывается на точные повторения по календарю. Если число часов нельзя получить повторяющимся шаблоном, заявка отражается среди пропусков. Для занятий с разовыми переносами нужен календарь исключений. Группа в расчёте резервируется целиком, включая практики с пометкой о подгруппе. В собственном наборе непересекающиеся подгруппы можно задать отдельными ресурсами и перечислить их вместе для общей лекции.

## Критерии и алгоритм

Поиск использует собственную конструктивную эвристику и локальное улучшение. Сначала строятся допустимые окна по типу недели, длительности и доступности. В приоритете оказываются заявки с малым числом подходящих назначений. На каждом шаге индекс занятости отсекает конфликтующие ходы. Затем генератор пробует переносить занятия, учитывая изменение штрафа у затронутых групп и преподавателя. Несколько стартов меняют порядок заявок и просмотра допустимых окон. На большом наборе сравнивается выборка допустимых окон. Это ограничивает вычисления и может оставлять пропуски даже при существовании лучшего решения.

Качество измеряется суммой **P = Σ wᵢ mᵢ**. Чем меньше значение при одинаковой нагрузке, тем лучше. Окно — перерыв между соседними занятиями от 60 минут. Перегрузка — пять и более пар за день. Дисбаланс вычисляется для каждой группы или преподавателя за неделю как **Σ(dᵢ − d̄)²**, где dᵢ — число пар в день. Каждый день заданной сетки участвует в подсчёте, включая пустые. Лабораторная на две пары добавляет две единицы нагрузки. Итоги суммируются по ресурсам и неделям.

Профиль **комфорта** усиливает штрафы за окна, одиночные занятия и перегрузки групп. **Компактность** повышает стоимость каждого активного дня. **Баланс** повышает стоимость дисбаланса и перегрузок. **Компромисс** учитывает также нагрузку преподавателей. Численные веса доступны в `planner/weights.py`. Показатель «Общий штраф» во всех строках вычислен с одними компромиссными весами. «Штраф профиля» и вклады критериев рассчитаны с исходными весами соответствующего профиля.

При включении `--adaptive` после начального размещения измеряется частота каждого штрафа на один ресурс-день. Поисковый вес умножается на **1 + 0,6 × min(1, √частота)**. Ограничение роста предотвращает доминирование одного критерия после плохого старта. Для отчёта сохраняется исходная шкала оценивания. Компактность и равномерность могут требовать противоположных переносов, поэтому сравнивайте также число назначенных заявок и исходные показатели. Пропуски учитываются отдельно. Поиск отдаёт приоритет большей полноте внутри одного профиля.

Для сходства строится множество **T** из четвёрок «заявка, неделя, день, номер пары». Длинное занятие входит всеми парами. **J(A,B) = |Tₐ ∩ Tᵦ| / |Tₐ ∪ Tᵦ|**. Для двух пустых множеств J = 1. При J > 0,98 вариант отбрасывается. Для каждой уже принятой альтернативы требуется хотя бы одно совместно назначенное занятие в разное время. Перестановка кабинетов или исключение занятий сами по себе не дают новый вариант. Во время поиска сохранение прежнего времени у уже показанных занятий получает дополнительный штраф. В жёстко ограниченной задаче допустимых различных вариантов может быть меньше запрошенного количества.

## Настройки, измерения и пределы

`search_config.json` содержит число вариантов, попытки на вариант, максимальное число посещений заявок на одну попытку локального улучшения, общий лимит времени поиска в секундах, уровень случайности и переключатель адаптации. По умолчанию каждый запуск получает случайный seed. Чтобы задать его явно, укажите `--seed` в консольном режиме или добавьте целочисленное поле `seed` в JSON-конфигурацию. Значения CLI имеют приоритет над файлом. Пример для трёх альтернатив с адаптацией:

```powershell
python raspisanie_sgu.py --data examples --variants 3 --attempts 4 --max-iterations 800 --time-limit 30 --randomness 0.4 --seed 17 --adaptive --summary-only
```

Бюджет времени делится между оставшимися профилями и стартами. Подготовка исходных данных измеряется отдельно. Лимит кооперативный: подготовка доменов, текущая операция и итоговая проверка могут завершиться после контрольного момента. При достижении лимита времени воспроизводимость по одному seed зависит и от скорости компьютера.

Статические домены времени и допустимых кабинетов хранятся раздельно. Поиск использует предварительную фильтрацию по вместимости и оснащению, битовые маски занятых минут, кэш часто встречающихся интервалов и локальный расчёт изменения штрафа. При отсутствии допустимого хода возвращается частичное расписание с пропусками. Такой результат не доказывает невозможность задачи. Назначенные занятия проходят отдельную проверку перед выводом.

В `benchmark_results.json` для фиксированных и адаптивных весов сохранены пять пар запусков на идентичных данных, с одинаковыми seed и бюджетами. Чередуется порядок запуска режимов. Лучший, средний и худший штрафы считаются по полным решениям на общей шкале. Отдельно приводятся время, конфликты, пропуски, окна, пустые и перегруженные дни, дни с одной парой и дисбаланс. Для выбора рабочих весов сравнение стоит повторить на нескольких семестрах с подтверждённой нагрузкой. Эта эвристика и серия измерений не устанавливают глобальный оптимум.
